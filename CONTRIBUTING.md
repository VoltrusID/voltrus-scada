# Contributing to Voltrus SCADA

Thanks for helping. This is the open-source Core of Voltrus SCADA. Bug reports,
protocol fixes, documentation and focused features are all welcome.

## Before you start

* For anything larger than a small fix, open an issue first so we can agree on
  the direction. The Core is deliberately scoped to what one site needs. Features
  that belong to the paid Enterprise add-on (single sign-on, 21 CFR Part 11,
  IEC 62443 audit mode, hot standby, multi-site hub, RTSP video, white-label,
  scheduled PDF and SMS reports) are not accepted into this repository, see
  [docs/open-core.md](docs/open-core.md).
* Security problems: do not open a public issue, see [SECURITY.md](SECURITY.md).
* Name and logo: the Voltrus trademarks stay with JoyoDigitama, see
  [TRADEMARKS.md](TRADEMARKS.md). Forks must rename.

## Development

```bash
cargo fmt --all
cargo clippy -- -D warnings
cargo test

cd client
npm ci
npx tsc --noEmit
npm test
```

CI runs the same checks. Keep changes focused, add tests for behaviour you
change, and keep the web client working when add-on endpoints are absent
(they return 404 in Core).

The DCO alone only says you may submit the code under the project licence. The
project is open core: the Core is AGPL and the Enterprise add-on is sold under a
commercial licence, which also lets companies that cannot use the AGPL license
the Core commercially. To keep that possible without chasing every contributor
later, we need the broader licence grant in point 2. It is a licence, not a copyright
assignment, and it does not let anyone take your contribution out of the AGPL
version that you contributed to.

If your employer owns your work, make sure you are allowed to contribute it
under these terms.

## Pull requests

* Branch from `main`, keep one topic per pull request.
* Describe what changed and how you tested it. Tick the sign-off box in the
  pull request template.
* Do not commit secrets, customer data, or files generated by builds
  (`static/`, `client/dist/`, `*.db`).
